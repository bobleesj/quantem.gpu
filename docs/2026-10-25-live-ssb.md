# Live SSB from a detector stream on one GPU (2026-10-25)

## Question

Can one GPU reconstruct a continuously scanning 4D-STEM acquisition while it is being acquired: each
512 x 512 scan of 192 x 192 uint16 patterns (about 13 s per frame at 20,162 patterns/s) refit for
defocus and two-fold astigmatism and reconstructed before the next frame completes, with every frame kept
on the GPU in lossless form and the memory use visible while it fills?

## Setup

- Detector stream: the DECTRIS DAQ simulator (`daqsim` 26.10.22) replaying recorded HDF5 acquisitions
  through the vendor stream (Stream2 CBOR over ZeroMQ), same host, no RDMA.
- Data: a measured 90-frame time series, 512 x 512 scan, 192 x 192 detector, 300 kV,
  30 mrad, 0.373 A scan step, recorded at 20,162 patterns/s.
- Reference: one fifth-order broad fit on the first frame; scan-detector rotation fixed.
- One RTX PRO 6000 Blackwell (96 GB). Receivers: `io.DetectorStream` (Python, this package) and the
  NVIDIA Holoscan SDK 5 ZeroMQ ingest of a separate pipeline, connected through `io.BatchFeed`.

## API

```python
ptycho = DirectPtycho(data, backend="cuda", scan_detector_rotation_deg=rotation_deg)
fit = ptycho.fit_aberrations(search="broad")
live = ptycho.listen("tcp://127.0.0.1:31001", fit, method="phase", save_dir="live-results")
# returns at once; the frame panel grows row by row (preview_every_rows=16) while the detector scans
live.report()           # per frame: C10/C12/phi12, drift, kept_in_vram, acquisition_s, processing_s, kept_up
live.show()             # interactive Show2D view: current frame and combined image, updated in place
live.show(mode="static")  # latest frame, combined image, drift as one figure
live.show(mode="vram")  # GPU memory over the run and the refit optics per frame
live.close(); live.release()
```

`listen` accepts an address (opened as `io.DetectorStream`) or any receiver whose `series()` yields
acquisitions with `start` and `batches()`; `io.BatchFeed` adapts push-style receivers. Each complete
frame is assembled by `io.LiveAcquisition` into the same lossless resident store `io.load` builds, then
goes through the per-frame step `series` uses (`_FrameStep`).

## Results

| Test | Result |
|---|---|
| `LiveAcquisition` from decoded batches vs `io.load` | every one of 262,144 patterns bit-identical after the same flagged-pixel correction; SSB phase difference 0.0 rad |
| `listen` vs `series` on the same recorded frames | refit optics, drift and latest/combined images identical |
| `io.DetectorStream` loopback | 156,000-177,000 patterns/s received and decoded, 7.7-8.8x the detector rate, bit-exact |
| simulator -> `DetectorStream` -> `listen`, 3 frames | patterns complete; results equal `series`; 0.4-0.7 s processing per 12.8 s frame |
| simulator -> Holoscan ingest -> `BatchFeed` -> `listen`, 90 frames | results equal `series` for all 90; processing median 0.41 s, max 0.77 s per 12.98 s frame; 24 frames (32 GB) retained before the announced stop; peak 74 GB |
| paced offline replay, 90 frames, GPU alone | all kept up (median 0.36 s, max 0.82 s); 36 frames (49 GB) retained; peak 75 GB |

Lossless retention costs 1.32-1.41 GB per frame against 19.3 GB as uint16 (about 13.7x). The
reconstruction working set is about 19-20 GB, measured on the first frame and kept free as a reserve.

### Row by row

SSB spectra are linear in scan rows, `G[bf, q_r, q_c] = sum_r exp(-2 pi i q_r r / R) rfft_cols(I_bf[r, :])[q_c]`,
so `ssb.cuda.rows.RowSpectra` adds each block of 8 arriving rows to resident spectra in place (one CUDA
kernel) and renders the frame so far through an ordinary session at the last refit optics. Unscanned rows
hold each bright-field pixel's running mean, which changes only the `q_c = 0` column, so the unscanned area
is flat. The preview borrows the previous frame's session, so it adds no memory beyond the run's.

| Test | Result |
|---|---|
| completed row spectra vs the engine's spectra of the same frame | 3.6e-7 relative; render equal to offline to 4.5e-8 rad (ssb), 8.9e-8 rad (phase) |
| cost | 22 ms per 32-row block (batched GEMM; 16 ms per 16 rows); 42-48 ms per render |
| simulator -> `DetectorStream` -> `listen`, 5 frames, preview every 16 rows | 31 previews per frame; 0.8-1.9 s preview + 0.4-0.7 s final per 12.8 s frame; results equal `series` |
| simulator -> Holoscan ingest -> `listen`, 5 frames | 1.2-1.6 s preview + 0.44-0.73 s final per frame; results equal `series` |
| browser, live view while streaming | zoom and a drawn profile on the frame panel unchanged from a 304-row preview to the final frame |

Rows are added in blocks because each update reads and writes all of the spectra once: the Holoscan ingest
delivers one scan row per batch, and one update per row would cost about 9 s per frame.

### Faster detectors

The detector's minimum frame time at 192 x 192 is 33.3 us (30,000 patterns/s, 8.7 s per frame). Updating
the row spectra with one batched complex GEMM (cuBLAS, in place) and drawing previews only in spare time
(the loop's own work plus one more preview under 80% of the elapsed time) keeps every rate tested:

| Source | Rate | Previews per frame | Final step | Lag after last pattern |
|---|---|---|---|---|
| recorded frames on a continuous clock | 20k / 30k / 60k / 120k | 31 / 30 / 28 / 14 | 0.37-0.38 s | 0.37-0.70 s, not growing |
| simulator -> `DetectorStream`, 8 frames | 30k | 31 | 0.31-0.60 s | results equal `series` |
| simulator -> Holoscan ingest, 8 frames | 30k | 31 | 0.42-0.72 s | results equal `series` |

With previews every 16 rows at all times and the spectra updated every 8 rows, 120k fell behind by 1.35 s
per frame.

## Conclusions

- At this detector rate the GPU is busy about 3-5% of each frame for refit + SSB + phase-only +
  registration; reconstruction keeps up with large margin.
- A live frame is bit-identical to the recorded file loaded with `io.load`, so live results equal offline
  results exactly.
- Retention policy: keep frames while the next frame's reserve stays free; stop retaining (announced)
  rather than evict. Kept frames are released, oldest first and announced, only when memory taken outside
  the run would otherwise fail the next frame.

## Rejected or deferred

- Resident-store byte equality as a parity criterion: compressed size depends on batch boundaries; decoded
  values are the criterion.
- Calling the detector's HTTP API from inside the receiving pipeline: the simulator serves one request at a
  time and a trigger request returns only after its series is delivered, which deadlocks the pipeline.
  Read the pixel mask before triggering.
- RDMA and GPUDirect delivery: not tested (no RDMA interface on the test host).
