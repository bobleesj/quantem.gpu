# CUDA HDF5 saving, 2026-11-07

Saving seven complete 512×512×192×192 uint16 acquisitions from resident ANS
to bitshuffle/LZ4 HDF5 took 48.26 s in the original application check. The
revised writer took 25.91 s, including file flush, publication and journal.
Both runs wrote 17.40 GB and passed full decoded-count and calibration checks.
These were shared-device observations, not a hardware-limit measurement.

## Bottleneck and change

The original writer decoded at most 32 MiB per batch, then made separate
host transfers for the compressed allocation size, chunk offsets and sizes.
A profiled single scan took 5.57 s: decode calls occupied 1.58 s and compression
plus transfer occupied 3.44 s. The HDF5 writer overlapped those operations;
its 1.83 s cannot be added to the critical-path times. Final durable flushes
took 0.48 s in that short observation.

The revised CUDA integer writer decodes at most 128 MiB, with a default limit
of 2,048 patterns. At 192×192 uint16 this becomes 1,820 patterns. Explicit
smaller `batch_size` values still apply. The acquisition remains ANS encoded;
compression and transfer scratch are additional to the bounded decode buffer.
Generic block algorithms and MPS keep their existing batch defaults.

One transfer now supplies the allocation size and complete chunk-offset table.
Chunk lengths are differences of those offsets. The packed-byte copy already
waits on the current stream, so a separate default-stream synchronization is
unnecessary. Compression kernels, stored dtype, decoded values, corruption
checks and file durability are unchanged.

Interleaved full-scan observations on the same source were 8.37 and 9.37 s
before, versus 4.46 and 3.54 s after both changes. A larger batch alone took
6.71 and 5.69 s. Changing only transfers had unstable results as competing GPU
work changed. Deferred decode-error checks were explored and not adopted.

## Sustained storage

Thirty consecutive saves cycled eight full acquisitions, retaining their ANS
sources and keeping all exports until verification. Every save included file
and directory flushes and a journal update. These are repeated saves, not
thirty separately triggered acquisitions.

| Workload | HDF5 save time | Acquisition time at 30,000 patterns/s |
| --- | ---: | ---: |
| First 20 saves | 124.67 s | 174.76 s |
| All 30 saves | 178.11 s | 262.14 s |

The save-only rate was 44,155 patterns/s, with a 6.06 s median and
3.42–10.19 s range. Flush calls accounted for 120.99 s of the 178.11 s;
conversion, queued writes and publication took the remaining 57.12 s, about
1.90 s per scan. Output totaled 74.75 GB. The local ext4 NVMe volume was
97–98% full, with competing reads and elevated write latency. Its available
bandwidth, not the advertised sequential specification, limits this run.

Average saving was faster than the stated acquisition rate, but the slowest
save exceeded one 8.74 s acquisition interval. Buffering and concurrent
acquisition/save validation remain necessary. The current managed application
serializes explicit acquisition and save commands. No simultaneous-acquisition
claim follows from this measurement.

## Verification and limits

GPU: NVIDIA RTX PRO 6000 Blackwell, device 0. Baseline revision: `db8523c`.
The candidate is the implementation accompanying this report. Python 3.12,
h5py 3.16.0, HDF5 1.14.6; four CPU library threads. Other CUDA jobs and disk
traffic remained active. Compiler and OS caches were uncontrolled. Loading,
streaming, saving and reopening were timed separately.

The real CLI check used seven distinct native Holoscan outputs with exact
uint16 values and resident calibration retained. Reopen verification took
10.68 s outside the HDF5 save timer. QEM was unchanged and took 17.24 s in this
shared-storage run; its earlier 7.11 s observation is not a matched comparison.

Nineteen focused checks passed. They cover encoded uint8/uint16 counts,
four-byte algorithm outputs, current-stream ordering, shard boundaries and
existing CPU/CUDA save contracts. Four MPS cases were explicitly deselected;
this is not MPS or native Swift qualification.

The private evidence archive is `20261107-hdf5-save` in
`quantem.gpu-experiments`: stage profiles, interleaved experiments, the native
seven-scan CLI check, scripts, source hashes and the candidate patch. Neither
these timings nor local file flushes establish simultaneous hardware
acquisition, RDMA, NAS durability or browser performance.
