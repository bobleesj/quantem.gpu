## Question

Does the prevalidated decode-table fast path improve the seven-source large-ADF
update when paired with the currently best scan512 polar-query path, while
preserving exact full maps and the established memory ceiling?

## Fixed protocol

- apple-m5-24gb Apple M5, seven distinct full `(512, 512, 192, 192)` uint16 sources.
- No cropping, binning, clipping, or count conversion.
- Keep scan512 enabled in every arm; toggle only trusted-table on/off.
- A1 trusted-table off, B on, A2 off; one warmup and 20 measured cycles per arm.
- Measure `adf-center-8` followed by `adf-center-20` in every cycle.
- Require exact full-map hashes on all seven sources for every cycle, identical
  source identities, all residents released, and memory no greater than the
  ordinary-offset reference: 11,877,814,048 resident bytes and 11,883,921,408
  Metal allocated bytes.
- Timings are detector-update wall times, not UI FPS or load latency.

The trusted table is generated by the internal deterministic factory and
validated before the resident loop starts. This is not a trust bypass for
arbitrary serialized tables. Pipeline preparation is outside the timing
boundary; resident allocation and all update work remain inside the evidence
gates.
