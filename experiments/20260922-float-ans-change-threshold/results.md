# Route ordinary aperture changes to the parallel decoder

The native trace showed 739 of 815 detector updates changed fewer than 1000 pixels. The previous 1600-pixel threshold left most ordinary movement on the serial decoder. Lowering the threshold to 384 sends these medium edits to the paired-state parallel kernel; very small edits and resets keep the existing serial path. The full float32 ANS resident remained 100×100×256×256 at scan bin 1, detector bin 1, crop none, and about 0.73 GB allocated in the app.

Same-source native A/B/A, 720 input positions per gesture and three trajectory repeats: large-ADF-center actual distinct presentations were 96.7 / 106.5 / 96.0 updates/s for threshold 1600 / 384 / 1600. Reduction p50 was 9.28 / 7.61 / 9.25 ms and p95 was 11.19 / 8.36 / 11.19 ms. Other candidate gestures were ABF center 101.8/s, ABF resize 101.6/s, and ADF resize 107.0/s, within observed control ranges. Comparing decoder variants at threshold 384 gave paired-state / independent-entropy / paired-state ADF-center presentations of 106.5 / 102.4 / 106.5 updates/s. The final default app, which compiles only the selected parallel pipeline, again presented 106.7/s with 7.53 ms p50 and 8.55 ms p95. It opened the real acquisition, switched BF/ABF/ADF/iDPC, displayed FFT, drove scan and detector gestures, and exited without recorded problems or console errors.

A real 128×128 compatibility fixture matched, SHA-256 `cf3d274b6e6b3c68b927e0bb853019dc509f261d664ec834209d2a18b09baacc`. A synthetic 8×8×256×256 file containing finite values, NaN, +Inf and −Inf matched, SHA-256 `ab06fef95f78cae32adf47d26aa766db945344dffca511eb90f0832d9eddad2b`. The real 256 and synthetic trajectories each exercised 89 edits above 1600. The 120 FPS target is still **not** met by the difficult ADF gesture; the fastest observed native result here is about 107 FPS.
